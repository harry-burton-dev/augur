# 0070. Data Atlas draws military symbols for its kinds with milsymbol

- **Status:** Proposed
- **Date:** 2026-11-05
- **Decided by:** Harry (overnight approval of the alpha's records, 5 Nov; the Data Atlas next-phases spec, N4, asks for "milsymbol (MIT) draws APP-6 / MIL-STD-2525 symbols from a code")

## Context

An operations floor reads units, vessels, aircraft and installations as military symbols (NATO's APP-6, the US MIL-STD-2525). A symbol says at a glance what something is and whose it is, and people who work with them expect to see them. Data Atlas shows every kind with a Lucide icon, which can't say "hostile armoured unit". The symbols are defined by a code (a SIDC) and drawn to the standard's rules. Drawing them by hand would be a great deal of work, and it would break the rule against hand-written SVG.

## Options

1. **Lucide icons only.** Nothing to add. Military kinds look like any other.
2. **milsymbol** (MIT, Måns Beckman, maintained since 2015). It draws APP-6 and 2525 symbols, letter and number codes alike, from a code, as SVG or canvas. It has no dependencies and ships its own types. It is large: about 850 KB minified.
3. **A symbol font or a sprite sheet** of chosen symbols. Small, but it covers only the symbols picked in advance, and the codes can't be combined freely.
4. **Server-drawn images** from a symbol service. It needs one more service, and deployments that can't call out would need to host it.

## Decision

Data Atlas draws military symbols with **milsymbol**, in its frontend only.

- **Where the code lives.** A kind may carry a symbol code in the ontology (`symbol`, on `ontology_types`), set in the studio. The service checks only its form: letters, digits, `-` and `*`, 10 to 30 characters. The studio says whether milsymbol can draw it before it's saved.
- **Where it's drawn.** The symbol shows beside the kind's name on the entity page, on the kind's row in the studio, and in the list of entities. The explorer's nodes keep their dots for now. Every kind keeps its Lucide icon, used wherever there's no symbol.
- **How.** milsymbol is loaded with `import()` only when a kind on screen has a symbol, so floors that don't use symbols never download it. It is drawn as an `<img>` from a data URL, never put into the page as markup, and it has words beside it (the kind's name) for screen readers.
- **Colours and SVG.** A symbol's frame colour is part of the standard: blue for friend, red for hostile, green for neutral, yellow for unknown. It carries meaning, so it is drawn in the standard's own colours, not the design tokens. This is the one exception to ADR 0015's token rule, and it applies only to symbols. The SVG is generated by a maintained library from a code, which is not the hand-written SVG the rule forbids.

## Consequences

- Military floors see the symbols they expect. Others see no change and download nothing more.
- One new dependency in Data Atlas's frontend, kept current by Renovate. Its size is why it is loaded only when needed.
- Symbol codes are stored as text, not checked against the standard in the service. A code milsymbol can't draw shows the kind's icon instead, and the studio says why.
- Drawing symbols on explorer nodes needs an image program for Sigma.js. That is a later change, with its own record if it needs a dependency.
- The check that holds the rule is Data Atlas's tests: a kind with a symbol code shows it, a kind without one shows its icon, and a code that can't be drawn says so in the studio.
