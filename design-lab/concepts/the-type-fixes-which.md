# The type fixes which, not what

Every entity hangs on one record, its type (specimen), set once and never moved. The type says *which thing*; it never says *what is true of it*, so the type can be wrong in what it says and still be the right anchor. Names, keys and facts change around it; a split brings back each part that holds its own type, with its old id, and a part with no type is new. From the botanical code's type method (ICN), where a name stays with its type through every revision.

First found in: [`2026-11-05-the-type-specimen`](../runs/2026-11-05-the-type-specimen/) (identity V2, merge V2 and V4, combined). The subsidiary's type is an invoice that quoted the wrong company number; it is still the anchor.

Could steer: Artifacts (a document's identity through renames and copies), Mandate (an intent that is split in two), Explorer (apps renamed or replaced), any import into Data Atlas.
