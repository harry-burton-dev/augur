# Four things must hold

A symptom-based procedure: name the few things that must be true (sign-in works, every part answers, the data fits the code, the way back exists), check them in order, let the first that fails send you to that part's own table (not stop the reading there), and check them all again after every act. In the run's walk-throughs it was the only card that got a tired operator through a safe restore. It never asks why, and it doesn't trust notices written by the thing that failed. From nuclear plants' critical safety function status trees.

First found in: [`2026-11-05-the-quick-reference-handbook`](../runs/2026-11-05-the-quick-reference-handbook/) (card V2, combined U-1 step 1; scenario world W2 and step 15). Tabletopped by walk-through: see the run's `checks/results.md`.
